# Contributing to Cardio

Thanks for contributing to Cardio. This project covers sales intelligence, staged analysis and LLM gateway.

## Before contributing

- Search existing issues and pull requests before filing a new one.
- Explain the user problem, expected behavior and scope. Keep changes focused.
- Do not include credentials, private customer data, location histories, or unlicensed third-party content.
- Check the repository's current licensing and attribution requirements before redistributing code or assets. Public visibility alone does not grant a reuse license.

## Pull request checklist

- Describe the change and link related issues.
- Provide exact verification commands and results. Explicitly mark any tests you could not run.
- Add regression coverage or explain why it is not applicable.
- Document configuration changes, data sources, API changes and known limitations.
- Use synthetic or authorized public test data, and remove secrets from logs and screenshots.

## Project-specific review considerations

Do not claim live web research or durable Temporal execution where the current implementation does not provide them. Test quotas, authentication and interrupted analyses.

## Reporting vulnerabilities

Do not disclose exploit details in public issues. Check GitHub's private vulnerability reporting option or contact the maintainers through an available private channel.

## Review process

Maintainers review correctness, user impact, documentation and compatibility. A pull request is not guaranteed to be merged.
